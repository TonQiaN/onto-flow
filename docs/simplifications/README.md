# 简化记录

一个简化候选一份文件，记它的证据、提议、放弃了什么、怎么验收——这是 `find-simplifications`
skill 的产出物，也是「为什么这块没了 / 为什么这块留着」的唯一存放处。AGENTS.md 只在
「Decisions and the glossary」里指向本文，**否决理由不回流 AGENTS.md**：AGENTS.md 每个会话整份进
上下文，多一句就是长期的 token 税；这里的记录只在需要时读。

## 目录与文件名

```
docs/simplifications/
  proposed/   已提出、未实施（skill 每轮的产出落在这里）
  done/       已实施并合并；移入时补「## 落地」，此后冻结
  rejected/   已否决；状态行带一句理由，保留到理由失效
```

文件名 `yyyy-mm-dd-slug.md`：日期是首次提出的日期，slug 用英文短横线（与 `docs/adr/` 同款）。
状态变化只移动文件、不改文件名。`src/rules.test.ts` 机械核对下面的骨架；`rejected/` 的审计与删除
由 skill 每轮执行。

## 骨架

```markdown
# 简化：<动作式标题>

状态: proposed          ← 或 `状态: done` / `状态: rejected — <一句理由>`，与所在目录一致

## 问题
点名文件、路由、表、导出；把**生产消费者**与**测试 / 文档消费者**分开列，附 rg 到的调用点。

## 提议
删什么、折什么、搬到哪；连带的测试、README、DESIGN 行、REVIEW 行、rules.test.ts 断言一起列。

## 放弃了什么
最强的反方：这块删掉后做不到的事、将来可能想要它的场景。

## 验收
可观察的终态与门：命令、e2e spec、必要时的付费冒烟或 dryRun 证据。

## 风险
行为变化、公开面变化、与已记录理由（AGENTS.md / ADR / docs/harness）的冲突及其解法。
```

`done/` 的记录另有 `## 落地`：PR 链接、与提议的差异、验收实际跑了什么。

## 分工

- **三条全中的决定才写 ADR**（难逆、脱离上下文令人费解、真有取舍）；记录里链过去，不重复。
- 记录是提案本身，不再另开 issue；实施 PR 的正文链接记录，合并时把记录移到 `done/`。
- 否决只有当它同时确立了一条**代码必须遵守**的规则时，才在 REVIEW.md 加一行；那是少数。
- 语料分类：生产 = `src/` 非测试文件、`scripts/seed*.ts` / `smoke-*.ts` / `run-*.ts`；
  非生产 = `*.test.ts`、`e2e/`、`docs/`、README、注释；`_reference/` 永不计。

## 保留期

- `done/`：移入后只补 `## 落地`，此后冻结；不随代码后续演变更新（代码归 git 历史）。唯一的例外是链接
  维护：被引用的记录换了目录，指向它的相对链接要跟着改——`src/rules.test.ts` 机械核对所有相对 `.md`
  链接都解析得到。
- `rejected/`：保留到理由失效——被否决的对象已不存在，或理由已被后来的 ADR / 决定覆盖——
  由 skill 每轮审计并删除。
- `proposed/`：不过期；要么实施，要么否决。

## 何时跑 skill

按需，以及每个里程碑收尾时跑一轮（不自动、不定时）。第一轮在 2026-09 清理的六批全部合并后
（[DESIGN-V3](../DESIGN-V3.md) 第 5 批）。

# JSON 产物交付前验收，契约使用 Harness 已执行的子集

JSON 形态的产物在 Action 成功前必须解析，并符合受理时冻结的对象类型契约；JSON 输入在受理前做同样检查。仅所选出口参加验收，文本和文件形态仍只检查文件存在且可读取。失败文件和字段诊断归本轮证据，不能交给下游；模型执行完成、契约通过、业务质量验收是不同事实。本决定替换 [ADR-0008](0008-artifacts-not-values.md) 的「文件存在是唯一机械兜底」，保留经文件交流。

理由：文件存在不能证明 JSON 可被消费者读取，错误字段曾让整条工作流假成功。契约直接使用已安装的 Harness 校验器，与 Tool 的执行子集一致，不引入第二套完整 JSON Schema 方言；对象类型写入时拒绝未支持的关键字，样例按钮和运行边界共用它，运行后改库也不能改写历史契约。代价是用户只能声明这一子集（例如不能使用 `$ref` 或 `minimum`），轮次需要保存验收证据；它证明交付形状，业务含义仍须由工作流自己的评审或完成门禁验收。

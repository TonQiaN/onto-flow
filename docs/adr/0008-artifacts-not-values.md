# Action 之间只经工作区文件交流，连线只生成"去读哪个文件"

Action 的实质产出不再作为值沿连线传给下游，而是写成工作区里的产物文件。每次执行交出双通道
结果：数据面是结构化输出，只放下游用来路由与判定的少数字段；上下文面是产物文件，放全部实质
内容。连线因此变哑——它不搬运内容、不做转换，只表示"下游要读上游的这份产物"，并据此在下游
提示里生成那一句"去读哪个文件"。

端口与对象类型保留，但语义随之改写（修订 [ADR-0002](0002-nominal-port-typing.md)）：对象类型
绑定的不再是"值的类型"而是"产物的契约类型"，同名才能连的约束只在编辑期成立；绑在输入节点上
的对象类型另有一项运行时实职，声明这份输入落盘后要做什么预处理。

> 2026-08-31：上段末句已被 [ADR-0011](0011-bash-in-session-no-platform-preprocessing.md) 废止——
> 平台不再预处理，格式转换在 Action 会话内用 bash 完成，对象类型回到纯契约类型。

理由：长文本作为值传递会被完整拼进每一个下游 Action 的提示，扇出时还要乘以分支数，按每工作流
每日 1000 次调用的规模这是主要的成本来源；写成文件后，下游按需读、人也能直接检视与比对，
文件系统工具与人工检查零成本复用。代价是类型约束退化为编辑期的连线检查——运行时没有任何机制
核对文件里真的写了它声称的东西，产物没写出来是唯一的机械兜底。

> 2026-09-05：[ADR-0020](0020-json-artifact-contracts.md) 替换「文件存在是唯一机械兜底」：
> JSON 产物在交付前校验内容契约，文本和文件形态仍只检查产物文件；文件作为交流通道的决定保留。

# 运行页画冻结的图，编辑器不跟随运行

推翻 docs/DESIGN.md 当时的「多路运行的界面契约」（画布运行条、`?runId=` 深链、并行切换器、
「回画布看动画」）。看一次运行只有一个地方：`/runs/<id>`。受理时把图——节点、坐标、端口与
出口名、连线——与 `runs` 行同一事务冻结进 `runs.graph`，运行页只读它，从不再查
`workflow_nodes` / `workflow_edges`；早于这个决定的运行拿到一张空图，同一条渲染路径，不留旧数据分支。
每个节点的每一次执行有自己的记录（`run_node_rounds`：轮次、会话、起止、
终态、所走出口、这一轮的输入输出与快照；输入、输出与被跳过的节点也各占一行，因为回边重置的是
下游全部节点），事件带会话归属（`run_events.session_id`）；页面持有 run、轮次与事件，一个纯函数
`visualsAt(t)` 从单一时间光标推出任一时刻每个节点处于哪一轮、什么状态、哪些连线已激活、当下的活动
（取消、整运行失败与重入耗尽这些不属于任何一轮的终态，按 `run_nodes` 的终态与时刻叠加）；
进行中的运行把光标钉在「现在」跟着 SSE 走，已结束的运行沿底部时间轴拖动回放，事件被清理后
退化为节点级；点节点开抽屉看轨迹、输入输出与快照，轨迹与光标双向联动。编辑器只编排与发起：
运行对话框拿到 runId 即跳运行页，`?runId=`、运行条、切换器与视觉上下文整体移除；导航
「运行中」面板与工作流卡片深链运行页；监控台 Trace 并入运行页的时间轴。

理由：运行会活过图的下一次编辑，画布上的跟随画的是现图，只对进行中的运行凑合成立，历史一
打开就对不上；同一条 SSE 对已结束的运行本就先回放全部事件再结束，直播与回放是同一份数据的
两个光标位置，分两处实现只会各自漂移——「回画布看动画」只在运行中显示、Trace 甘特另推一套
span，就是分两处的结果；而 `run_nodes` 一个节点只有一行，回边重入会覆盖它的起止与出口，不另存
轮次就回放不出「第 1 轮打回、第 2 轮通过」。代价：`runs` 多一列几 KB 的图、多一张轮次表、事件多一列；编辑器不再能边编排边看运行，看动画
要多一次跳转；多路并行的切换从画布运行条退到运行列表与导航面板。

# 运行输入一律物化为工作区文件

延伸 [ADR-0008](0008-artifacts-not-values.md)：实质内容走产物文件的原则同样适用于
**运行输入**。运行启动时，`materializeRunInputs` 把发起人提供的每个输入落进
`workspace/inputs/<输入节点id>/`——文件类拷原件（ADR-0011 原样物化不变），文字物化为
`<节点名>.md` 并一字不差，JSON 以缩进两格的确定格式物化为 `<节点名>.json`。此后引擎内
的 PortValue 一律是文件引用：提示里只给路径（与 Action 读上游产物同一种读法），`describeInput` 再遇到
内联值即响亮失败。对外 API 的入参形状不变（照收 `kind: "text" | "json" | "file"`），
统一发生在物化层，不转嫁给调用方。运行详情的可见性由新增的只读预览通道
`GET /api/runs/[id]/files` 兜住——它同时补齐了产物内容在界面上一直看不到的旧缺口。

理由：输入是这次运行最初的产物，却是「实质内容不沿连线复制进提示」原则的唯一例外——
例外本身就埋雷：内联路径里藏着超过 200 字符即静默截断的特判，超长题目喂给模型的是
残句且无任何报错。物化为文件后，输入与产物只有一种读法，截断特判连同 text/json 内联
分支一并删除，工作区目录自身即完整叙事（翻目录就能看到这次运行从什么开始）。代价：
每个文字/JSON 输入多一轮 `read` 工具调用（几秒与少量 token）；运行详情不再直接展示
输入正文，看内容要经预览通道多点一下；分界点之前的内联历史记录不迁移，也不保留兼容
展示，按本机可再生运行数据处理。

# 用具名出口端口表达分支，允许回边，工作流图不再是 DAG

扇出与汇总都退化为图的形状而不是节点类型：一个出口端口连出多条线就是并行扇出，一个输入端口
接进多条线就是汇总。分支判定由 Action 的**具名出口端口**承担——节点声明"通过 / 打回"这样的
出口，执行完按自己的数据面结果选中一个，只有被选中的出口上的连线才激活；连线本身不带任何条件。
出口端口连回上游 Action 即构成循环，被回流的那个 Action 声明自己最多重入几次以及次数耗尽时按
失败还是按接受收束。循环的每一轮都是全新的会话，上一轮的产物与评审意见经工作区文件传给下一轮。

理由：目标是把 Claude 那种 fan-out-synthesis 与 review-fix 的编排能力交给人手工编排与调试，
而不是交给模型动态决定。判定放在节点里、连线保持哑，是为了在画布上一眼看见两条分支各通向哪
——条件藏在边里就得逐条点开才知道为什么没走。循环每轮开新会话而不是续跑同一会话，是为了让
上下文不随轮数膨胀，并让每一轮都能单独重放。代价是 `src/lib/graph.ts` 的四条现行规则全部作废：
输入端口不再限一条入线、Action 不再要求所有输入端口已连线、环不再是校验错误、拓扑排序不再够用，
调度器要换成能处理回边与重入上限的形态。

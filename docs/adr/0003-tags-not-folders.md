# 用标签而非文件夹组织各个库

五个库（Workflow / Action / Skill / Tool / Object Type）的分类维度是**多归属的标签**，
不是单归属的文件夹树。标签名可用 `/` 表达层级（`采购/集采`、`能力/审核类`），列表页
左侧把标签按层级渲染成可折叠的树，**看起来像文件夹，语义上仍是标签**——同一个实体
可以同时出现在多棵子树下。交互骨架照搬 Dify 的资源列表：防抖搜索 + 多选标签过滤 +
排序 + 筛选状态同步到 URL + 分页。

理由：Action 的数量会远多于 Workflow，且天然是多维的（业务域 × 能力类型），单归属
文件夹会逼用户反复纠结"这个到底该放哪"，并在复用时产生错误的归属暗示。层级命名 +
树状渲染保住了"文件夹式浏览"的直观，代价是没有真正的目录唯一路径（重命名标签是
全局操作，而不是移动一个文件夹节点）。ComfyUI 的工作流浏览器是真文件夹树，但那是
因为它的工作流本就是磁盘上的文件；我们的实体在数据库里，不背这个约束。

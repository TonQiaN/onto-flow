# 每次运行一个 harness 子进程，一个独立工作区

Next 长驻进程只做编排：每次运行 spawn 一个 harness 子进程，把为这次运行生成的组合配置交给
它，经 stdio JSON-RPC 驱动其中每个 Action 的会话；取消就是终止这棵进程树。每次运行在数据根
下拥有唯一目录，`workspace/` 是全部 Action 的会话 cwd 与唯一交流场所，运行之间互不可见。
工作流声明要用的技能与工具，运行初始化时以 symlink 指向全局库的活目录导入，并把每一项的
内容摘要写进运行记录。

理由：dsh 上游的 settings、credentials 与 MCP 客户端都是进程全局的，按运行分进程让"每个运行
有自己的一套 harness 设置与 MCP 集合"不需要改造上游任何一项；崩溃隔离退化成进程树终止，
HMR 重建也炸不到在跑的运行。按每工作流每日约 1000 次模型调用推算约 110 次运行/天，十个并发
子进程的内存代价可以接受。symlink 而非拷贝快照是明知代价的选择：磁盘成本归零、全局库修好的
技能下次运行即生效，代价是运行不再自包含——内容摘要只能证明"跟那次是不是同一份"，证明不了
能把旧内容取回来；为避免已受理的付费运行中途断链，受理边界会持有其 Skill 投影，库中删除立即
生效但目录删除延迟到最后一个持有者和子进程完全收束，因此删库后的投影可能短暂继续占用磁盘。
